Avant la pratique

C’est quoi Claude Code ?

Imagine que tu ouvres un dossier sur ton ordinateur et que tu demandes à un assistant de t’aider dedans. Pas juste de parler du projet. De le lire, de proposer une action, de créer un fichier, de corriger une erreur, puis de t’expliquer ce qui a changé.

Claude Code sert à ça. C’est un agent de code. Il peut travailler dans le terminal ou dans l’interface Desktop. Il est pratique pour apprendre, créer un site, corriger un script, organiser un projet ou comprendre une erreur. Mais il faut garder une règle simple : tu demandes, il propose, tu vérifies.

Question simple

Est-ce que je veux seulement une explication, ou est-ce que je veux obtenir un vrai fichier dans un vrai dossier ? Cette question t’aide à savoir quand utiliser Claude Code.

01

Un assistant dans ton projet

Claude Code est un outil d’Anthropic qui se lance dans un dossier de travail. Il ne regarde pas juste une question isolée : il peut comprendre les fichiers autour, proposer une modification et t’aider à avancer sur un vrai projet.

02

Pas seulement un chatbot

Un chatbot répond surtout dans une conversation. Claude Code peut aussi agir : créer un fichier, modifier du code, lancer une commande, expliquer une erreur ou préparer une checklist. C’est utile, mais ça demande plus de contrôle.

03

Tu restes le pilote

Claude Code propose et exécute, mais toi tu décides. Tu lis ce qu’il veut faire, tu regardes les fichiers modifiés, tu ouvres le résultat, puis tu acceptes ou tu demandes une correction. L’outil ne valide pas à ta place.

04

Le dossier compte beaucoup

La règle simple : Claude Code travaille là où tu le lances. Si tu l’ouvres dans le bon dossier, il a le bon contexte. Si tu l’ouvres au mauvais endroit, il peut regarder ou modifier des éléments qui ne concernent pas l’exercice.

La boucle à retenir

  1. 1. Tu ouvres le bon dossier.
    Claude Code doit partir du bon contexte.
  2. 2. Tu formules une demande claire.
    Tu dis le résultat attendu, le public et les contraintes.
  3. 3. Claude propose ou modifie.
    Il peut écrire, corriger, lancer une commande ou expliquer.
  4. 4. Tu vérifies.
    Tu ouvres le fichier, tu lis le diff, tu testes le rendu.
